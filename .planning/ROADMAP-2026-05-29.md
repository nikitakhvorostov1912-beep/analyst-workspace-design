## 4. North Star и модель уровней L0–L6

**Отличительная способность — «объяснять почему».** Не «найти», не «написать код» (это 1С:Напарник), а **диагностировать и обосновать** с пруфами.

| L | Уровень | Смысл | Рынок | Мы | Где у нас |
|---|---|---|---|---|---|
| L0 | Lexical | имена, поиск по строке | есть у всех | ✅ | MCP (оболочка) |
| L1 | Structural | структура метаданных | EDT, Code Index | ✅ | **M-K1** done |
| L2 | Relational | граф вызовов/связей | MetaVision, bsl-graph(alpha) | 🟡 | **M-K3** (граф) — впереди |
| L3 | Semantic | смысл (embeddings) | Напарник(writing), bsl-atlas | ✅/🟡 | **M-K2** done; улучшение в M-K4 |
| L4 | Behavioral | «почему» (diagnose) | **ПУСТО — наша ниша** | ⬜ | **M-K3/M-K4** — главный USP |
| L5 | Normative | стандарты ИТС/БСП | **ПУСТО** | ✅/🟡 | **M-K2** RAG done; compliance в M-K4 |
| L6 | Predictive | предсказание последствий | **ПУСТО — moat** | ⬜ | **M-K5/M-K6** |

**Принцип лестницы:** каждый уровень требует предыдущих. L4 («почему») невозможен без L2 (граф) — поэтому **M-K3 строит L2-граф, без которого diagnose в M-K4 не взлетит**. Это объясняет, почему забегать в M-K4-reasoning, не достроив M-K3-граф, — тупик.

> - **G0 (жёсткие гейты, иначе не релизим):** ноль выдуманных фактов · метка источника (типовая/база/не подтверждено) · НЕ молчит/не зацикливается · гард «типовое≠клиент». *Текущий дефект #38 (цепочка молчит до лимита) = нарушение G0.3 — блокер.*

> - **Ценность = граф (как должно) + MCP (как есть) + честная метка**, не граф в одиночку. Самый надёжный сценарий — «откуда движения/цифра».
> - **Сейчас:** движения/RLS проходят G0/G1 на единичных вопросах (44/44 без галлюцинаций); golden-set из практики НЕ собран (нужен пользователь); слепого теста нет. **Релиз клиенту — только после golden-set прогона + слепого теста.**

## 8. Сквозные принципы (не нарушать)

1. **Local-first.** Индексация и embeddings — локально на машине аналитика (FastEmbed ONNX, не Docker/Ollama). Код клиента не уходит в облако без явного opt-in. Базовое compliance-обещание (152-ФЗ/КИИ).
2. **Grounded.** Любой ответ Knowledge Layer ссылается на `file:line` + объект метаданных + стандарт ИТС/БСП. Ответ без grounding = баг. (Anti-hallucination guardrails — первый кирпич этого, уже в репозитории.)
3. **Per-configuration isolation.** Каждая база клиента — отдельный индекс `~/.analyst-1c/knowledge/<fingerprint>/`. Никаких глобальных индексов между конфигурациями (кроме reference-типовых для L6).
4. **Incremental.** Не переиндексировать всё; mtime-watcher + diff-based update; полная переиндексация только по fingerprint mismatch.
5. **Test-first для каждого UC.** UC = запрос + ожидаемый ответ. Реализация начинается с golden-кейса, не с кода.
6. **Trace везде.** Каждый ответ = развёрнутый ToolTrace (какой workflow, какие источники, промежуточные результаты).
7. **Open-core boundary.** Open: indexing pipeline, AST-парсер, graph-схема, MCP-скелет. Closed: reference-библиотека типовых, business-semantics rulebook, готовые knowledge-бандлы.
8. **Anti-goals.** Не делаем свой LLM; не делаем редактор кода (мы analyzer, не IDE); не пишем код за пользователя (это Напарник); не индексируем чужие базы на нашем cloud; не покупаем Neo4j/Kuzu (SQLite CTE достаточно); не proprietary embeddings; не macOS/Linux до commerce-launch.
