## Правила интеграции

### ✅ Прими без вопросов (high-confidence предложения)

Это вещи которые правда полезны и согласуются с архитектурой `analyst-workspace-design`:

- **Capability Discovery Protocol** через `experimental.analyst-1c.features` в MCP `initialize` (см. 02-PROTOCOL-AND-FLAGS.md)
- **Двухрежимная архитектура EPF / CFE** с общим ядром (см. 03-DELIVERY-MODES.md)
- **Capability matrix** — 8 базовых + 15 расширенных = 23 capabilities (см. 01-ARCHITECTURE.md)
- **Feature flags pattern** на frontend через `useCapability` hook + `FEATURE_MODULES` registry
- **UpgradeCTA компонент** для disabled фич вместо просто скрытия
- **Тройной RAG источник** — v8std (317 стандартов) + БСП API + .hbk платформы
- **5 MCP параллельно** через MCP Orchestrator с unified tool registry (префиксы `toolkit.*`, `buddy.*`, ...)
- **HMAC SSO в CFE режиме** для seamless авторизации от 1С-пользователя
- **Activity Stream + Posting Trace** карточки — CFE-only фичи через подписки на события

### 🔄 Сравни с твоим планом и интегрируй лучшее

Эти решения у тебя могут быть **по-другому или лучше**:

- **Декомпозиция фаз** — у меня 8 фаз (12-18), у тебя может быть другая нумерация/группировка. Сохрани свою если есть смысл, импортируй только содержание задач.
- **Timeline** — у меня 16 недель с параллелизацией. Если у тебя другая оценка (больше или меньше) — оставь свою.
- **Phase 16 (MetaVision)** — у меня форк + CLI режим. Возможно у тебя другой подход (GUI integration через subprocess), он может быть лучше — оставь.
- **Параллельные треки** — у меня 13b+14, 16+17 параллельно. Если у тебя другая комбинация — оставь свою.
- **Onboarding wizard изменения** — у меня step 1 расширен выбором EPF/CFE. Если у тебя другой UX — оставь свой.

### ⚠️ ОБСУДИ с пользователем перед интеграцией

Не принимай молча — спроси у пользователя:

1. **CFE подсистема vs префикс `АП_`** для именования объектов 1С (см. Q1 в 08-OPEN-QUESTIONS.md)
2. **Какие типовые поддерживать**: только УТ 11.5 / + ERP / + КА / + БГУ (см. Q2)
3. **EPF first или CFE first** (см. Q3)
4. **Лицензионная модель** (open source / коммерческий / dual) — влияет на встраивание tools_ui_1c GPL-3.0 (см. Q6)

Если у тебя в плане эти решения **уже приняты** — оставь свои.

### ❌ Отклоняй с обоснованием

Не интегрируй если у тебя обоснованно по-другому:

- **Свой формат capability protocol** — если у тебя уже свой стандарт (например `serverInfo.metadata`)
- **Другая декомпозиция режимов** — например 3 режима вместо 2 (EPF/CFE/Cloud)
- **MetaVision полностью** — если у тебя нет планов на интеграцию (риск задержки 4 недели)
- **Тройной RAG** — если у тебя одного источника достаточно по scope
