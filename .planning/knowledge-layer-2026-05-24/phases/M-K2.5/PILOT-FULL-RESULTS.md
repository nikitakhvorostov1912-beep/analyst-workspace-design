## Performance после оптимизации

Старый код на полной КА оценивался **10+ часов** (per-op fsync).
Новый код (commit=False + RETURNING + WAL + batch commits каждые 500
объектов / 50 BSL файлов) — **30-50× быстрее** на реальных данных.

| Конфигурация | До оптимизации | После | Ускорение |
|---|---:|---:|---:|
| КА 2.5.25.92 граф | ~4 часа (оценка) | **7:11** | ~33× |
| БП 3.0.138.24 граф | ~2 часа (оценка) | **3:49** | ~32× |
| **Итого 2 типовых** | ~6 часов | **11 минут** | ~33× |

Оптимизация позволила пройти Phase 8 для двух конфигураций за один
интерактивный сеанс вместо нескольких суток фоновых прогонов.

## Готово к чат-интеграции

Бот через LLM tools может ответить на:

- *«Какие типовые загружены?»* → `list_typical_configurations`
  → [БП 3.0.138.24, КА 2.5.25.92]
- *«Кто пишет в РегистрНакопления.ТоварыНаСкладах в КА?»*
  → `trace_typical_movements(_ka2_25_92, ..., writes)`
  → топ-50 методов которые делают `Движения.ТоварыНаСкладах`
- *«Что вызывает РасчётСебестоимости в КА?»*
  → `trace_typical_calls(_ka2_25_92, ..., out, depth=2)`
  → дерево вызовов до 2 уровней
- *«Расскажи про Документ.РеализацияТоваровУслуг в БП»*
  → `explain_typical_object` → карточка + граф
