## Топ-5 BLOCKER (чинить ДО релиза)

### B-1. `--bg-hover` CSS-переменная **не определена нигде**, но используется в 8 файлах
Грубая ошибка в design-tokens — компонент-уровневые hover-фоны в shell, dropdown, command palette, status, export button **резолвятся в `unset` → unset в CSS = `inherit` → невидимый hover**. Особенно фатально в light theme (sand): hover пропадает совсем.

**Файлы:**
- `frontend/components/shell/ChannelSelector.tsx:183,248` — главный селектор баз 1С без hover
- `frontend/components/ui/dropdown-menu.tsx:43` — все dropdown'ы без hover (Header, ChannelSelector)
- `frontend/components/ui/command.tsx:70` — Cmd+K palette
- `frontend/components/ui/CopyButton.tsx:64`
- `frontend/components/chat/ExportSessionButton.tsx:76`
- `frontend/app/status/page.tsx:541,676`
- `frontend/components/cards/CodeCard.tsx:147`

**Доказательство:** `grep --bg-hover frontend/styles/design-tokens.css` → 0 матчей. Переменная только используется, никогда не объявлена.

**Fix:** Добавить в `:root` `--bg-hover: var(--bg-2);` и в `[data-theme="light"]` `--bg-hover: var(--bg-2);` (или явно `#ededed`). Это **5 минут работы**, эффект — hover-affordance на ~30% интерактивных элементов починится.

**Критичные места:**

Brand semantic токены `--success/--warning/--error` существуют — ими не пользуются.

Это **2-3 часа** работы по поиску-замене, эффект — light theme выживает, dark становится консистентным.

### B-4. Двойной заголовок «Модель ИИ» + дубль описания в LLMConfigForm
Заявлено пользователем — подтверждаю по коду:

- `frontend/app/settings/page.tsx:108-114` — `<h2>Модель ИИ</h2>` + `<p>Языковая модель, которая читает ваши вопросы и обращается к базе 1С.</p>`
- `frontend/components/settings/LLMConfigForm.tsx:443-445` — `<label>Модель ИИ</label>` сразу под этим (на 12px → выглядит как подзаголовок)
- `frontend/components/settings/LLMConfigForm.tsx:484-489` — под Select сразу после выбора: `{activePreset.model.description} · {activePreset.provider.label}` — это **тот же текст что в SelectItem дроп-списке** (line 462-464), потому что `preset.description` уже отображается рядом с `preset.label` в каждом item. Получаем визуальный дубль.

**Подтверждение второй части:** SelectItem-блок (lines 459-466) использует `<div className="flex flex-col">` — это даёт multi-line высоту item'у и при свёрнутом SelectTrigger показывается через `<SelectValue />` (line 451), что для радикс-Select означает рендер выбранного `<SelectItem>` целиком. Раз SelectItem имеет 2 строки → trigger показывает 2 строки → trigger становится двойной высоты, текст центрируется неровно. Это та же проблема, о которой говорил пользователь.

**Fix:**
1. Убрать `<label>Модель ИИ</label>` из LLMConfigForm (заголовок секции уже есть в settings/page).
2. SelectItem рендерить плоско: `<span>{label} <span className="text-fg-3">— {description}</span></span>`, иначе для SelectValue передавать только `label` через `<SelectValue placeholder={label}>` или кастомный renderer.
3. Описание под селектом `{activePreset.model.description}` — удалить, оно уже в дроп-листе.

То же самое в `MCPConnectionForm.tsx:241-256` — поле «Порт обработки в 1С» имеет под собой `<p>Тот же номер, что введён в MCP_Toolkit на вкладке «Встроенный сервер»…»</p>` — упоминание «MCP_Toolkit» как технического термина (см. B-3) + дубль интента с placeholder «6010».

### B-5. Light theme catastrophically broken в нескольких экранах
Brand-гайд утверждает поддержку обеих тем. Реальность:

1. **Все hardcoded `*-red-*` / `*-green-*` (см. B-2)** — на песочном фоне неоновые, контраст < 3:1 в части мест
2. **Scrollbar** в `globals.css:28-34` — hardcoded `#262626` / `#303030` → на cream-фоне это **тёмные жирные полосы**, выпадают из brand
3. **`--bg-hover` undefined** (B-1) — особенно в light: dropdown items, command palette, channel selector — без hover вообще
4. **`bg-[var(--bg-elevated)]` legacy alias** — резолвится в `--bg-1` = `#faf8f3` для light. Внешний контейнер `bg-[var(--bg)]` = `#f3f1ec`. Разница в **3 единицы по lightness** — карточки практически сливаются с фоном. Нужно либо увеличить контраст light-theme `--bg-1`, либо менять стратегию (карточки на light = `--bg-2` для surface)
5. **`bg-black/60 backdrop-blur-sm`** в Dialog (line 18) и CommandPalette (line 109) — в light theme overlay становится **серым на песочном** через прозрачность, выглядит грязно
6. **AssistantMessage error block** — `bg-red-950/30` + `text-red-300` — в light это **тёмно-серый на песочном** + **бледно-розовый текст** = нечитаемо
7. **ConnectionStatusBanner** — `bg-red-950 text-red-200 border-red-700` — на песке абсолютно нерелевантно, банер выглядит как ошибка рендера
8. **`focus:bg-[var(--bg)]` в SelectItem** (line 118) — `--bg` = bg-0 (сам фон). На light это `#f3f1ec` поверх `#faf8f3` (dropdown bg) — focus **темнее не становится**, исчезает совсем

**Fix:** проверить вручную каждую страницу в light theme и привести к sand-палитре через переменные.

## Pillar 1 · Visual consistency — 5/16

### Findings

**HIGH-1** Хаос фоновых токенов: используется одновременно `bg-[var(--bg)]`, `bg-[var(--bg-0)]`, `bg-[var(--bg-1)]`, `bg-[var(--bg-elevated)]`, `bg-[var(--bg-2)]`. Settings page: `bg-[var(--bg)]` (line 63) → внутри `bg-[var(--bg-elevated)]` (lines 92,108). Дальше Memory/Insights/Skills Links используют `bg-[var(--bg-1)]`. Это **три разных granularity** в одном экране. **Fix:** определить единый набор: shell = `--bg-0`, карточки = `--bg-1`, raised = `--bg-2`. Удалить legacy aliases `--bg-elevated` и `--bg`.

**HIGH-2** Border-radius несовместимы. На `/settings`: section'ы `rounded-lg`, форма внутри `rounded-md` (line 220 MCPConnectionForm). Header buttons `rounded-md`, StencilChip `rounded-full`, KindCard в форме `rounded-md` — на одной странице 3 разных скругления плотным группами.

**HIGH-3** В `/insights` локальный `EmptyState` компонент (line 316-322) дублирует существующий `components/ui/EmptyState.tsx`. У них **разные стили** (локальный без иконки/CTA, глобальный — с акцентной иконкой в кружочке).

**MEDIUM-1** Версия в `Header.tsx:48` = `1.2.4`, а в `StencilLockup.tsx:34` default = `1.2.2`, а в `app/about/page.tsx:174` написано «Версия 1.2.1». Минимум **три разных версии** в коде одновременно — пользователь видит разные числа на разных экранах.

**MEDIUM-2** Brand StencilChip определён, но `KindBadge` (в /settings, /status, в ChannelSelector dropdown) использует его, а custom-chip в insights table (`<th className="...font-normal text-[11px] uppercase tracking-[0.12em]">`) — нет. У них разный font-family, разный padding, разный letter-spacing. Brand-pattern должен быть один.

**MEDIUM-3** Inline-стили `style={{ fontFamily: "var(--font-jb-mono), ...}}` повторяются в 11 файлах (Header.tsx, ChannelSelector.tsx, Sidebar.tsx, SessionList.tsx, Input.tsx, ChartCard.tsx, StencilLockup.tsx, GuideLayout.tsx, SectionHead.tsx, Marker.tsx, AppShell.tsx). Это значит Tailwind утилиты `font-jb-mono` нет → инлайны как костыль. Должен быть `font-mono` или новый `font-jb` через tailwind config + plex / jbmono в font-family.

**MEDIUM-4** `tailwind.config.ts` — старый v3-стиль с `theme.extend.colors / fontFamily / transitionDuration`. Но `globals.css:1` использует `@import "tailwindcss"` — это Tailwind v4 синтаксис. **v4 игнорирует config файл, если нет `@theme inline { … }` директивы или `presets`**. Это значит `bg-bg-1`, `text-fg-3`, `duration-normal`, `ease-design-ease` — **не работают как утилиты Tailwind**. Используются только через `bg-[var(--bg-1)]` arbitrary, что и видно в коде. Config-файл = мёртвый. См. `components/onboarding/OnboardingDialog.tsx:55` — `duration-normal ease-design-ease` — это NO-OP.

## Pillar 3 · Affordance & feedback — 9/16

### Findings

**HIGH-5** Destructive button (`button.tsx:19-20`) использует `bg-red-800 text-white hover:bg-red-700` — не из brand-системы. Это применяется на «Удалить LLM конфиг», «Удалить подключение», «Сбросить локальную базу» — все деструктивные действия выглядят чужеродно в Stencil. **Fix:** `bg-[var(--error)] text-[var(--brand-ink)] hover:bg-[var(--error-20)]`. (Сейчас в LocalDataSection.tsx:109 уже сделано правильно, но в самом button.tsx variant — нет.)

**HIGH-6** Test button («Тест», «Тест подключения») возвращает feedback **только через toast** (LLMConfigForm.tsx:353-369, MCPConnectionForm.tsx:206-217). Toast pops up наверху-справа, исчезает за 3-4 секунды → если пользователь моргнул, он не знает ответил ли сервер. Нет inline-индикатора результата возле кнопки. **Fix:** добавить inline-результат (StencilChip success/error прямо в форме рядом с кнопкой).

**MEDIUM-6** `MCPConnectionForm.tsx:373-378` — кнопка «Тест» disabled если `!initial?.id` (т.е. новое неподохранённое подключение). Но `title`/`aria-label` не объясняет почему. Подсказка `"Сначала сохраните, потом тестируйте"` показывается только при клике (через toast). Лучше disabled-стейту дать tooltip.

**MEDIUM-7** В `LLMConfigForm.tsx:642-660` — последовательность кнопок: «Тест» (secondary), «Сохранить» (default), «Удалить» (destructive). Visual weight — Default бренд-оранжевая основная → правильно. Но Delete справа = противоположная по эмоциональной нагрузке кнопка стоит на том же уровне → primary action ('Сохранить') и destructive ('Удалить') одинаково «громкие». **Fix:** Delete вынести в отдельную секцию ниже формы (или в outside menu кнопку).

**MEDIUM-8** Send button (`Input.tsx:432-447`) при canSubmit использует `bg-[var(--accent)] text-[var(--brand-ink,#15161a)]` — это правильно для brand. **Но** при `!canSubmit` (disabled) — `bg-[var(--bg-3)] text-[var(--fg-3)] cursor-not-allowed`. Между orange и серым нет переходного состояния, при наборе текста кнопка резко вспыхивает signal-цветом. Можно добавить `transition-colors` для плавности.

**MEDIUM-9** Focus-ring везде `focus-visible:ring-1 ring-[var(--accent)]` (button.tsx, input.tsx, select.tsx). 1px ring мало заметен на orange-accent в светлой теме (signal #FF6A3D vs sand #F3F1EC = 4.5:1 контраст, но толщина 1px слабо видна). Brand хорошо бы поднять до `ring-2 ring-offset-2 ring-offset-[var(--bg-0)]`.

## Pillar 6 · Accessibility — 5/20

### Findings

**HIGH-12** Контраст в light theme провален в 5+ местах (см. B-5). Например `text-red-300 bg-red-950/30` на песке = ярко-розовый текст на чёрном квадрате → fails WCAG AA in sand context.

**HIGH-13** `--bg-hover` undefined (B-1) → keyboard-focused list items в dropdown/command palette **не получают визуального состояния**. Это нарушение «keyboard focus indicator visible» (WCAG 2.4.7).

**HIGH-14** В `MCPConnectionForm.tsx:262-273` — radio-group `<input type="checkbox" id="anon_enabled">` использует `accent-[var(--accent)]` (native styling), но cursor: `<label htmlFor="anon_enabled">` имеет `cursor-pointer` только на label. Чекбокс получает фокус, label нет. Кликабельная область не покрывает label. Нативный аксенстайл работает, но мелкий.

**HIGH-15** Aria-labels иногда подменяются `title`. Например `Header.tsx:71-72` — search-button имеет `aria-label="Командное меню"` + `title=null`. Screen reader скажет «Командное меню» — но видимая надпись «SEARCH ⌘K». Несоответствие текста для screen-reader и зрячих → fails consistent labeling.

**HIGH-16** В `Header.tsx:91-92` — иконочные кнопки `<Activity>` имеют `aria-label="Диагностика"` + `title="Диагностика — проверить что всё работает"`. Хорошо. Но в `Sidebar.tsx:32-46` — кнопка «Новый чат» имеет только текст внутри, никакого aria-label. Visible label `Новый чат` достаточен, но иконка `<Marker />` в начале — без `aria-hidden="true"`, screen-reader зачитает оба элемента.

**MEDIUM-14** В `SessionList.tsx:84` — `window.confirm(...)` — native browser confirm. Это accessibility-friendly (стандартный диалог), но **полностью игнорирует brand** и стиль приложения. На критичных операциях (удалить чат) — выглядит как баг.

**MEDIUM-15** `MCPConnectionForm.tsx:264` — `<input type="checkbox">` имеет `id="anon_enabled"`, но это статичный id. Если две формы рядом (например, в onboarding и в settings одновременно — что возможно через Dialog), будет конфликт id. Должен быть generated id или useId().

**MEDIUM-16** Focus-ring везде `ring-1` — недостаточная толщина для людей с пониженным зрением. **Fix:** `ring-2 ring-offset-2`. Также в light theme accent оранжевый теряется на песке — нужен `ring-offset` иначе ring сливается с фоном.

**MEDIUM-17** `StencilChip` для button-варианта (asButton=true, line 64-77) использует `<button>`, но без явного `type="button"` — есть на line 67. ОК для chips. Но `Sidebar.tsx:32-46` кнопка «Новый чат» не имеет `type="button"` — если положить её в форму, она отправит её.

**LOW-4** `<Marker size={10} />` в Sidebar декоративный, но без `aria-hidden="true"`. Screen reader зачитает его как inline-svg.

**LOW-5** Disabled-state в Input («disabled:opacity-50», `input.tsx:12`) и в Button (button.tsx:7) — opacity 50% делает текст ниже 4.5:1 contrast. **Fix:** ставить `disabled:bg-[var(--bg-4)] disabled:text-[var(--fg-4)]` вместо opacity-блюра.

## Дополнительные системные проблемы (вне 6 столпов)

### Архитектурные

**ARCH-1** В layout.tsx:47 — `<html className="dark ...">` явно прописан класс `dark`. Но ThemeToggle меняет `data-theme="light"` через JS. Класс `dark` остаётся всегда → если где-то использован `dark:` Tailwind variant (его не нашёл, но возможен), он будет применяться при светлой теме тоже. **Fix:** убрать `className="dark"` из html, использовать только `data-theme`.

**ARCH-2** `frontend/lib/json-tree.tsx` — рендерит JSON-tree с `text-purple-300 / text-green-300 / text-red-400`. Это применяется в ToolTrace для отображения tool_call params/result. По логике пользователь не должен видеть JSON — но если он развернёт trace, то увидит дискордирующую цветовую схему **без переменных вообще**. Нужны brand-tokens для code/syntax.

**ARCH-3** На странице `/about` (about/page.tsx:33) написано «9 разделов: подключения · инструменты MCP · карточки …» — этот CTA-блок ведёт на `/guide`. Гайд указан как 9 разделов, но если зайти в `frontend/components/guide/` — это разные компоненты, не разделы. Нужно сверить со структурой гайда чтобы не было устаревшего числа.

### Текстовый контент

**TEXT-1** "Сначала сохраните, потом тестируйте" — toast в MCPConnectionForm.tsx:198-201. Странная формулировка, лучше: «Сохраните подключение, чтобы можно было его проверить».

**TEXT-2** На главной (page.tsx:271-274) — «модель сама подберёт нужные инструменты 1С, выполнит запросы и покажет ответ с таблицей или карточкой объекта». Слово «инструменты 1С» — это полу-технический жаргон. Аналитик может спросить «какие инструменты?» Лучше: «модель сама найдёт нужные данные в базе и покажет таблицу или карточку».

**TEXT-3** В insights — «(оценка)» в скобках в KPI labels («Токенов (оценка)», «Стоимость, USD (оценка)») — мелкая деталь, но если оценка не выводится при `data.estimated_tokens > 0 ? ... : "—"`, то когда нет данных показывается тире — и непонятно, оценка чего тире.
