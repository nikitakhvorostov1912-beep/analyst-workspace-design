# 01 · Дизайн-токены

> Файл: `frontend/styles/design-tokens.css`. Большинство правок системы — здесь.
> Меняем **значения** существующих переменных. Имена переменных НЕ переименовываем
> (на них завязан весь код и `@theme inline` в `globals.css`).

---

## 1.1 Тёмная тема (`:root`) — поверхности

Текущий холодный near-black меняем на тёплый (sand-подтон), убираем «грязные» серые.

| Переменная | Было | Стало | Назначение |
|---|---|---|---|
| `--bg-0` | `#0a0a0a` | `#0c0d10` | фон приложения |
| `--bg-1` | `#141414` | `#14151a` | карточки, header, sidebar (= Ink бренда) |
| `--bg-2` | `#1a1a1a` | `#1b1d23` | поповеры, hover карточек |
| `--bg-3` | `#202020` | `#24262e` | code, раскрытые состояния |
| `--bg-4` | `#262626` | `#2d2f37` | disabled inputs |

`--code-bg` / `--code-fg` / `--code-dim` оставить как есть (`#0d0e11` / `#e5e5e5` / `#5c5c5c`) — фирменный «code ground».

## 1.2 Тёмная тема — текст

Цель: тёплый белый + **три уверенные** ступени серого (конец войны с `#8a8a8a`).

| Переменная | Было | Стало | Контраст на `--bg-0` |
|---|---|---|---|
| `--fg-1` | `#e5e5e5` | `#f3f1ec` | ~17:1 (AAA) |
| `--fg-2` | `#cccccc` | `#bdbbb4` | ~9:1 (AAA) |
| `--fg-3` | `#b0b0b0` | `#a4a29b` | ~6.5:1 — placeholders/hints |
| `--fg-4` | `#888888` | `#8c8a83` | ~4.8:1 — только декор/disabled |

> Важно: `--fg-4` (≈4.8:1) — **только** для крупного/декоративного текста, не для
> читаемых подписей. Eyebrow’ы и мета-подписи переводим на `--fg-3`.

## 1.3 Тёмная тема — акцент и семантика

| Переменная | Было | Стало | Комментарий |
|---|---|---|---|
| `--accent` | `#ff6a3d` | `#ff6a3d` | без изменений |
| `--success` | `#7cf0c4` | `#4fcf9a` | меньше неона, годен для текста |
| `--warning` | `#f7c948` | `#f0b429` | тёплая охра |
| `--error` | `#f87171` | `#f2675f` | без кислотности |

Производные `*-12 / *-20 / *-40` пересчитать под новые базовые цвета (та же альфа,
новый rgb). Пример для success: `--success-12: rgba(79,207,154,.12)` и т.д.

**Удалить «радугу» инфо-цвета как акцента.** `--info #5fb8ff` оставить только для
нейтральных hint-блоков, но в трейсе инструментов (см. 1.6) больше НЕ использовать
синий/зелёный/фиолетовый как категориальные цвета.

## 1.4 Светлая тема (`[data-theme="light"]`)

| Переменная | Было | Стало | Назначение |
|---|---|---|---|
| `--bg-0` | `#f3f1ec` | `#f1efe8` | sand-фон |
| `--bg-1` | `#faf8f3` | `#faf9f5` | карточки |
| `--bg-2` | `#e7e4dc` | `#ffffff` | raised/поповеры (чистый белый для глубины) |
| `--bg-3` | `#ddd9cf` | `#e9e6dd` | deepest |
| `--accent` | `#ff6a3d` (наследует) | `#e8551f` | **глубже** — держит AA на песке. Добавить блок ниже. |

В блоке `[data-theme="light"]` добавить переопределение акцента (его сейчас нет —
light наследует `#ff6a3d`, который на песке проваливает контраст для текста/иконок):

```css
[data-theme="light"] {
  /* ...существующие... */
  --accent:     #e8551f;
  --accent-08:  rgba(232,85,31,.08);
  --accent-12:  rgba(232,85,31,.12);
  --accent-20:  rgba(232,85,31,.20);
  --accent-32:  rgba(232,85,31,.32);
}
```

Семантику light оставить solid (как сейчас сделано правильно): `--success #2db98c`,
`--warning #c69314`, `--error #dc2626`. Текст `--fg-1..4` уже solid с проверенным AA —
**не трогать** (это была хорошая правка, см. комментарии в файле).

Нейтрали light-текста оставить: `--fg-1 #15161a`, `--fg-2 #2a2b2f`, `--fg-3 #4a4b4f`, `--fg-4 #6a6b6f`.

## 1.5 Удалить мёртвые accent-варианты

Блоки `[data-accent="blue"]`, `[data-accent="clinical"]`, `[data-accent="indigo"]`,
`[data-accent="orange"]` — это легаси отменённых редизайнов. Удалить их полностью,
оставить только `[data-accent="signal"]`. (Если код где-то читает `data-accent`,
зафиксировать `signal` как единственное значение.)

## 1.6 Трейс инструментов — убрать категориальную радугу

Файл `frontend/components/chat/ToolTrace.tsx`, объект `CATEGORY_STYLE`.
Сейчас 4 категории красятся в orange/blue/green/purple — это спорит с правилом
«оранжевый = только действие». Свести к **двум состояниям**:
- `ok` — нейтральный чип (`bg-2`, текст `fg-2`, бордер `bd-2`), при hover — `bd-3`.
- `error` — `error-12` / `error` / `error-20`.

Категорию (mcp/memory/todo/clarify) оставить как **иконку** (Wrench/Database/...),
а не как цвет. Один акцент на интерфейс.

## 1.7 Типографика

Базовый кегль тела поднять. Сейчас интерфейс на `text-sm`/`text-xs` (13–12px) —
утомляет. Новая шкала:

| Роль | Шрифт / вес | Размер | Где |
|---|---|---|---|
| Display | Plex Mono 700 | 28–40px | пустые экраны, hero онбординга |
| Heading | Plex Sans 600 | 18–24px | заголовки секций, диалогов |
| **Body** | **Plex Sans 400/500** | **15–16px** | ответы, описания, формы (было 13–14) |
| Small | Plex Sans 400 | 13px | вторичное |
| Data | JB Mono 500 | 13–14px | числа, длительности, запросы |
| Meta | JB Mono 400 | 11–12px | eyebrow/мета — **трекинг .1em** (было .18em) |

**Правила использования (вписать как комментарий в design-tokens.css):**
- IBM Plex Mono — логотип и Display. НЕ для рядовых подписей.
- JetBrains Mono — данные, код, дозированные eyebrow. Один eyebrow на секцию, не на каждый блок.
- Уменьшить трекинг uppercase-мета с `0.18em`/`0.16em` до `0.1em–0.12em` для читаемости.
- Тело ответа ассистента — `15px`/`line-height 1.6` (сейчас `text-sm` ≈ 14px).

## 1.8 Ритм, радиусы, тени (зафиксировать как ориентир)

- **Spacing:** шаг 4 — `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64`.
- **Радиусы:** `6px` контролы · `10px` карточки · `14px` диалоги · `999px` pill.
  (Сейчас разнобой `rounded-md/lg` — привести к этой шкале.)
- **Тени:** две ступени. `--sh-1: 0 1px 2px rgba(0,0,0,.4)`, `--sh-2: 0 8px 30px rgba(0,0,0,.45)`
  (light: мягче, см. референс). Добавить как переменные, использовать вместо случайных `shadow-sm`.

## 1.9 Самопроверка токенов

После правки `design-tokens.css`:
- [ ] `getComputedStyle(document.body).backgroundColor` в dark = `rgb(12,13,16)`, в light = `rgb(241,239,232)`.
- [ ] Ни один экран не «полусветлый» при переключении темы.
  ⚠️ **Грабли:** не вешать CSS `transition` на `background`/`color` (shorthand) у
  элементов, чьи токены меняются между темами — в некоторых движках значение
  «залипает». Транзишн — только на longhand `background-color`/`color`, или гасить
  переходы на момент переключения (добавить `[data-switching]` класс на `<html>`
  на 1 кадр). См. как сделано в `reference/app.js`.
