## Q1. CFE — префикс или подсистема для объектов?

**Контекст:** Внутри расширения нужно как-то именовать новые объекты (общие модули, регистры, обработки).

**Варианты:**
- **A. Префикс `АП_`** — `АП_ОбщийМодуль`, `АП_МониторингАктивности`. Меньше визуального беспорядка в дереве конфигуратора. Лучше для интеграции в большую типовую.
- **B. Подсистема `АналитикПлюс`** — объекты внутри подсистемы без префикса. Удобнее группировать. Стандарт БСП.

**Моя рекомендация:** **B + namespace в именах**. То есть подсистема + всё равно префикс для критичных объектов (общие модули) чтобы избежать конфликта имён.

## Q2. CFE — для какого набора типовых?

**Контекст:** УТ 11.5 / ERP 2.5 / КА 2.5 имеют общее ядро, но есть отличия.

**Варианты:**
- **A. Только УТ 11.5** — минимум усилий, фокус на одной конфигурации
- **B. УТ 11.5 + КА 2.5** — близкие, легко поддерживать
- **C. УТ 11.5 + ERP 2.5 + КА 2.5** — общее ядро, ~80% рынка
- **D. + БГУ + ЗУП** — универсально на БСП 3.1+, риск конфликтов

**Моя рекомендация:** **C** — общее ядро УТ/КА/ERP с фича-флагами внутри CFE.

## Q4. MetaVision — форк с CLI или wrapper над GUI?

**Контекст:** MetaVision GUI-only. Чтобы использовать headless нужно либо доработать, либо обходить.

**Варианты:**
- **A. Форк + CLI режим** — больше работы (1 неделя Java), но чистое решение
- **B. Wrapper над GUI** — Headless GUI через xvfb (Linux) или скрытое окно (Windows). Грязно, но быстрее
- **C. Отказ от inline graph** — кнопка "Открыть в MetaVision" запускает desktop app. Только связь с нашим UI

**Моя рекомендация:** **A**, с fallback на C если за неделю не получится.

## Q5. Code-signing certificate для installer?

**Контекст:** Windows SmartScreen ругается на unsigned .exe. Аналитик может бояться.

**Варианты:**
- **A. Купить cert** — ~$300/год (Sectigo, DigiCert), SmartScreen не ругается
- **B. Self-signed** — README с инструкцией "Подробнее → Выполнить в любом случае"
- **C. EV cert** — ~$500/год, immediate trust, нужна организация

**Моя рекомендация:** **B** для MVP, **A** для production если будем продавать.

## Q6. Бизнес-модель / лицензирование?

**Контекст:** Конечный продукт — open source или коммерческий? Это влияет на лицензии встроенных tools.

**Варианты:**
- **A. Open source MIT** — все встроенные компоненты должны быть compatible (tools_ui_1c GPL-3.0 — несовместимо!)
- **B. Коммерческий closed source** — gpL3.0 не подходит, нужно убрать tools_ui_1c или переписать
- **C. Dual license** — community free, enterprise paid

**Моя рекомендация:** **C** с разделением:
- Core (Multi-MCP, RAG, BSL LS) — Apache 2.0
- CFE / EPF — proprietary (свой код + указание авторов заимствований)
- Tools_UI_1C обработки — GPL-3.0 (если включаем) или альтернативы
