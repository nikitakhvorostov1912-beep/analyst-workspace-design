# ИТС-KB Eval — анти-галлюцинация (D1 из AI-SPEC)

Измеряет, насколько надёжно phantom-детектор (`app/knowledge/phantom_check.py`)
ловит выдуманные методы БСП, не флагая реальные.

## `golden.jsonl`

20 кейсов, по одному JSON-объекту на строку:

| Поле | Смысл |
|---|---|
| `id` | идентификатор кейса |
| `category` | `valid` / `phantom-FM1` / `mixed` / `not-found` / `client-context` |
| `query` | вопрос пользователя |
| `answer` | кандидат-ответ с вызовами `Модуль.Метод(...)` |
| `expected_phantom` | методы, которые ДОЛЖНЫ быть флагнуты как фантомы |
| `note` | обоснование (ground truth) |

**Ground truth grounded:** реальные методы скопированы из исходников
`tools/ssl_3_2/src/cf/CommonModules/<Модуль>/Ext/Module.bsl` (раздел
`#Область ПрограммныйИнтерфейс`, объявления `Функция/Процедура ... Экспорт`).
Phantom-кейсы верифицированы `grep`'ом как отсутствующие.

## Протокол расширения датасета

1. Реальный метод — копировать дословно из исходников БСП (не по памяти).
2. Phantom — правдоподобное имя, которого НЕТ в модуле (подтвердить `grep`).
3. Финальную валидацию подтверждает senior-методолог 1С (AI-SPEC §1b).

## Запуск

- Тест (засеянный in-memory корпус, CI): `pytest tests/test_its_kb_eval.py`
- На живом корпусе (нужен проиндексированный `bsp_chunks` в `app.db`):
  `python -m scripts.run_its_kb_eval`

## Метрики (цель)

- precision = 1.0 на golden (реальные методы не флагаются)
- recall = 1.0 на golden (все фантомы пойманы)
- production hallucination rate (phantom / ответы с вызовами БСП) < 5% (AI-SPEC)
