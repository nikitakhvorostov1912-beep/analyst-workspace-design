# Выжать максимум из Напарника (ИТС) — дизайн

**Дата:** 2026-06-07
**Ветка:** feature/m-k3-relational-cfe
**Статус:** approved (дизайн), ожидает план

## Проблема

На вопросы про методику/ИТС бот даёт **узкие ответы без ссылок**. Расследование показало: Напарник (`buddy.search_its`, 1C.ai Gateway на :6002) реально возвращает **синтез-ответ + 10 статей с прямыми URL на its.1c.ru + их doc_id**, но приложение это **выбрасывает**:

1. **Карточка не строится.** `cards.py:_CARD_BUILDERS` не содержит ни одного `buddy.*` → `build_card_from_tool_result("buddy.search_its")` всегда `None`. Ссылки попадают только в контекст LLM как markdown-текст и теряются, если модель сама не впишет их в прозу (а промпт велит «не вываливай сырьё» + «TL;DR 1 строка» → выкидывает).
2. **Полный текст статьи недоиспользуется.** `fetch_its` отдаёт компактный AI-дайджест статьи (~700-1000 токенов, проверено на `its-pubdevguide83-461-hdoc`), но модель зовёт его нестабильно.
3. **Провенанс** показывает только текст запроса (`tc.args`), не результат — ссылок там нет.

## Что НЕ является решением (проверено эмпирически)

«Читать сайт ИТС своим парсером» — **не работает**:
- Jina Reader (`r.jina.ai`) на its.1c.ru → **401, заблокирован** (bad IP / нужна авторизация).
- Прямой GET `its.1c.ru/db/pubdevguide83` → HTTP 200, но это **оболочка портала** (132 КБ nav+JS); текст статьи в iframe `/db/content/.../src/text/*.htm` **за подпиской**.
- `robots.txt` запрещает ботов (`GPTBot: Disallow: /`); автосбор под подпиской — риск ст. 272 УК РФ + блокировка аккаунта.

**Вывод:** легального программного доступа к контенту ИТС в обход Напарника нет. `fetch_its` (лицензированный шлюз) — единственный легальный «парсер статей». Дословный verbatim-текст — только в браузере пользователя с подпиской (не функция продукта).

## Решение (4 рабочих блока)

### W1. Карточка «Источники ИТС» (backend + frontend) — ядро

**Backend** (`app/orchestrator/cards.py`):
- Новый `_build_its_sources_card(args, result)`: из `result.content[].text` (markdown) парсит ссылки `[title](https://its.1c.ru/...)` и doc_id (`its-...-hdoc`/`hdir`) из секции «**Найденные документы:**». Сопоставляет title↔url↔doc_id по порядку/тексту.
- Новый pydantic `ITSSourcesCardPayload`: `sources: list[ITSSource]`, `total: int`, `card_id: str`. `ITSSource = {title: str, url: str, doc_id: str | None}`.
- Регистрация в `_CARD_BUILDERS` под ключи `"buddy.search_its"` и `"buddy.search_1c_documentation"` (имя приходит с префиксом — подтверждено: `build_card_from_tool_result` получает prefixed `tool_name`).
- Пустой/непарсящийся результат → `None` (карточки нет, поведение прежнее).

**Frontend** (`frontend/components/chat/`):
- Новый `ITSSourcesCard.tsx`: список источников. Каждый — внешняя ссылка (открывает `url` в новой вкладке, `rel="noopener noreferrer"`). У источников с `doc_id` — кнопка «Разобрать статью» (W2).
- Тип в `lib/types.ts` (card type `"its_sources"` + payload), ветка в рендере карточек (`AssistantMessage`/Message card switch).
- Бренд: без glow/gradient/glass; токены `--accent`, существующие компоненты-примитивы.

### W2. Кнопка «Разобрать статью» → fetch_its (frontend wiring)

- Кнопка у источника с `doc_id` → callback `onAsk(text)` с шаблоном:
  `Разбери статью ИТС «{title}»: вызови fetch_its(id="{doc_id}") и дай разбор.`
- `onAsk` отправляет обычное user-сообщение через существующий чат-send → модель вызывает `buddy.fetch_its`. Новый backend-эндпоинт НЕ нужен.
- Протяжка `onAsk` от карточки до send — по образцу существующего `onRepeat` (Message → Thread → page/useChatStream).

### W3. Промпт: авто-дочитывание топ-1 + анти-дубль + консервативный трим

- **Глубина:** на knowledge-вопросах модель делает `buddy.search_its` → затем `buddy.fetch_its` **самой релевантной (топ-1)** статьи → отвечает по обоим. Остальные статьи — пользователь добирает кнопкой. (Текущий промпт уже говорит «нашёл статью → fetch_its»; делаем директиву явной и стабильной. Кап `MAX_BUDDY_CALLS_PER_TURN=3` не трогаем: search+fetch = 2.)
- **Анти-дубль:** добавить «ссылки ИТС не дублируй текстом — они показаны карточкой». Снимает конфликт «цитируй ↔ не вываливай сырьё» и экономит output-токены.
- **Консервативный трим** (поведение не меняется, ~−20-35% от 22 535 симв): few-shot — 1 пример на категорию вместо 2-3; chart-примеры — 1 spec вместо 3; ужать verbose memory-секцию (правила оставить, длинные примеры сократить).

### W4. Тесты + smoke

- Backend: юнит на `_build_its_sources_card` (markdown→карточка: 10 ссылок+doc_id; пустой результат→None; результат без ссылок→None); регистрация builder для обоих buddy-ключей.
- Frontend: `ITSSourcesCard` рендер (ссылки + кнопка только при doc_id) + клик кнопки вызывает `onAsk` с корректным шаблоном.
- Smoke (живой ИТС-вопрос): карточка со ссылками появилась → клик «Разобрать» → разбор статьи. Замер: размер промпта до/после трима; число раундов на knowledge-вопрос.

## Вне scope

- Веб-скрапинг/парсинг its.1c.ru (нелегально + не работает).
- Дословный verbatim-текст статьи (только браузер пользователя).
- Описание 6 неиспользуемых инструментов Напарника (`ask_1c_ai`, `check_1c_code`, `modify_1c_code`, `explain_1c_syntax`, `diff_1c_documentation_versions`) в промпте — модель и так видит их в списке tools; в промпт-бюджет не лезем (отдельная возможная доработка).
- Изменение `MAX_BUDDY_CALLS_PER_TURN`, `apply_row_gate`, `TOOL_CONTENT_CAP`, поведения MCP-пути.
- Параллельный open-data RAG (страховка под 01.10.2026) — отдельная доработка.

## Влияние на токены

- W1 (карточка) — парсит то, что уже в контексте: **+0 LLM-токенов**, и убирает дубль ссылок в прозе (−output).
- W3 авто-fetch топ-1 — **+1 раунд** на knowledge-вопросах (~+30-50% токенов на них); дайджест статьи дёшев (~1k), дорога пересылка контекста. Частично компенсируется консервативным тримом (−20-35% на каждом раунде).
- Чистый эффект на простые data-вопросы (без ИТС): **дешевле** (трим), без потери поведения.

## Критерии приёмки

1. ИТС-вопрос → под ответом карточка «Источники ИТС» с кликабельными ссылками на its.1c.ru.
2. Ответ грунтован по топ-1 дочитанной статье (виден вызов `fetch_its` в трейсе).
3. Кнопка «Разобрать статью» у источника с doc_id → бот делает разбор именно этой статьи.
4. Системный промпт ужат на ≥20% без регресса на контрольных вопросах (data/knowledge/диагностика).
5. Бэкенд-тесты + фронт-тесты зелёные; smoke на живой базе пройден.
