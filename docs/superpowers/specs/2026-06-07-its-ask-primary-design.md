# ИТС: ask_1c_ai как основной источник + компактная карточка источников — дизайн

**Дата:** 2026-06-07
**Ветка:** feature/m-k3-relational-cfe
**Статус:** approved (дизайн), ожидает план
**Предыдущий цикл:** `2026-06-07-naparnik-its-value-design.md` (карточка ИТС + fetch + трим) — завершён.

## Проблема

На вопрос «как настроить RLS» для базы КА 2.5 карточка «Источники ИТС» забита статьями из чужих конфигураций (Фотоуслуги, ЖКХ, Медицина, лаборатория, автотранспорт, КАМИН) — мусор, не решающий задачу пользователя.

## Корень (доказано probe на живом Напарнике)

- `buddy.search_its` — **глобальный семантический поиск** по всему ИТС. Запрос «RLS» цепляет раздел «Ограничение доступа» из ЛЮБОЙ конфигурации. Параметр `configuration` — слабая подсказка, НЕ фильтр (Фотоуслуги/автотранспорт лезут во все выдачи независимо от конфы).
- `buddy.ask_1c_ai(configuration="Комплексная автоматизация")` — **config-aware синтез**: вернул чистый КА-2.5-ответ (НСИ→Группы доступа→флаг RLS, регламентное задание, профили групп, роль «Базовые права»), **ноль чужих конфигураций**.
- Доп. наблюдение: `search_its` дважды упал с `-32603 Internal error` (rate-limit/перегрузка beta-шлюза), `ask_1c_ai` отработал — ask надёжнее.

**Вывод:** для «как настроить / методика» мы используем НЕ ТОТ инструмент. Качество достигается не чисткой карточки, а сменой инструмента: `ask_1c_ai` для ответа.

## Решение

Стратегия: для knowledge-вопросов **ответ — от `ask_1c_ai(configuration)`** (чистый, под конфу), **источники — от `search_its(configuration)`** рядом, но компактной карточкой (топ-1-3 развёрнуты, прочие свёрнуты). `fetch_its` — только on-demand (кнопка «Разобрать»), НЕ авто.

### W1. Промпт (backend `loop.py` SYSTEM_PROMPT, buddy-блок)

Перестроить директиву buddy:
- **Knowledge / «как настроить» / «как правильно» / «что такое» / методика** (про платформу/конфу):
  ОСНОВНОЙ ответ — `buddy.ask_1c_ai(configuration=<конфа базы>, question=...)`. Это config-aware, чистый ответ под конкретную конфигурацию.
  ДОПОЛНИТЕЛЬНО — один `buddy.search_its(configuration=...)` для проверяемых источников (их покажет карточка «Источники ИТС»). НЕ вызывай `fetch_its` по умолчанию.
- **`fetch_its`** — только когда пользователь просит разбор конкретной статьи (кнопка «Разобрать» шлёт такой запрос).
- Ссылки ИТС в тексте не дублируй — они в карточке (сохранить из прошлого цикла).
- Data-вопросы → MCP базы (как было). Диагностика/многофакторное → `ask_1c_ai` (ИТС) + MCP база, синтез.

Заменяет директиву прошлого цикла «search_its → fetch_its топ-1» (авто-fetch убираем).

### W2. Гарантия конфы (backend `loop.py` `_inject_buddy_configuration`)

Сейчас подставляет `configuration` в `buddy.search_its` / `buddy.fetch_its`. **Добавить `buddy.ask_1c_ai`** в набор — `configuration` подставляется из детектнутой конфы канала (`ctx.buddy_config_name`), даже если модель не указала. Не перетирает явно переданное.

### W3. Ранжирование источников (backend `cards.py` `_build_its_sources_card`)

После парсинга — **стабильная сортировка**: источники платформы/методологии вперёд, остальные сохраняют порядок выдачи Напарника.
- Платформа/методология (вперёд) — по db-префиксу ИТС: `pubdevguide*`, `pubprof*`, `bsp*`, `v8std*`, exact `answers1c`. Это универсально-авторитетные источники «как 1С устроена/как правильно».
- Остальные — в порядке выдачи (ниже).
- Config-family буст (демоция ЗУП/БП для КА-базы) — **вне scope v1** (config-agnostic сортировка уже топит отраслевой шум: Фотоуслуги/ЖКХ/Медицина уходят вниз → в свёрнутое). Отмечено как follow-up.

### W4. Компактная карточка (frontend `ITSSourcesCard.tsx`)

- Развёрнуты **первые 3** источника (после backend-сортировки — это платформа/методология + топ-релевантные).
- Остальные **свёрнуты** под кнопкой «показать ещё N» (toggle, `useState`). Раскрываются по клику — ничего не теряем.
- Если источников ≤ 3 — кнопки нет, всё развёрнуто.
- Кнопка «Разобрать» у каждого с `doc_id` — без изменений.

### W5. Тесты + smoke

- backend: `_inject_buddy_configuration` подставляет config в `ask_1c_ai`; `_build_its_sources_card` сортирует платформу/методологию вперёд; SYSTEM_PROMPT содержит директиву «ask_1c_ai основной для knowledge».
- frontend: `ITSSourcesCard` развёрнуты 3, «показать ещё N» раскрывает остальные; ≤3 — без кнопки.
- smoke (живой): knowledge → `ask_1c_ai` чистый КА-ответ + компактная карточка (3 релевантных + свёртка); «дай ссылки/Разобрать» работает; data-вопрос → `execute_query` без ИТС.

## Вне scope

- Config-family ранжирование (точная демоция по конфе) — follow-up; config-agnostic топит отраслевой шум.
- Надёжность `-32603` (rate-limit Напарника) — отдельный риск, не лечим здесь (ask_1c_ai основной → меньше зависимость от flaky search_its; при ошибке ответ всё равно есть, карточки нет — мягкая деградация).
- Прочие инструменты Напарника (`check_1c_code`, `modify_1c_code`, `explain_1c_syntax`, `diff_*`).

## Влияние на токены/латентность

- Knowledge-вопрос: `ask_1c_ai` (~20с) + `search_its` (~15с) = 2 buddy-вызова (как и было: search+fetch=2; меняется состав, не число).
- Карточка/сортировка — +0 LLM-токенов (backend-парсинг).
- `ask_1c_ai` ответ компактнее дампа search_its → скорее меньше токенов в контексте.

## Критерии приёмки

1. Knowledge-вопрос → ответ от `ask_1c_ai`, в тексте нет чужих конфигураций.
2. Карточка «Источники ИТС»: 3 развёрнуты (платформа/методология сверху), прочие под «показать ещё N».
3. Отраслевой шум (Фотоуслуги/ЖКХ/Медицина) — в свёрнутой части, не вверху.
4. `ask_1c_ai` получает `configuration` базы (видно в трейсе / тесте инъекции).
5. Кнопка «Разобрать» (fetch_its) и data-роутинг (execute_query) не сломаны.
6. backend + frontend тесты зелёные; smoke на живой базе пройден.

## Очистка

Probe-скрипты этого цикла уже удалены. Финальный smoke не оставляет временных файлов.
